# PINN-SPMe

Physics-informed and supervised neural-network training for lithium-ion battery state estimation with SPMe models.

This repository contains the electrolyte-aware SPMe training workflow from generated SPMe CSV datasets.

It performs physics-informed state and parameter estimation for a single-particle model with electrolyte dynamics (SPMe) and SEI degradation. Three LSTM networks estimate the anode, electrolyte and cathode concentration states from current/voltage history; a differentiable SPMe rolls those states forward; and the SEI thickness is learned as a trainable parameter from voltage and lithium-inventory losses. The datasets in `data/` are generated by the MATLAB repository [ESCL-OU/LGM50](https://github.com/ESCL-OU/LGM50) (branch `yk-updates`); see that README's "PINN-SPMe dataset generation" section.

End-to-end pipeline:

```text
LGM50 (MATLAB)                                   PINN-SPMe (this repo)
1. degradation cycling run  -> checkpoint .mat   4. NN pretraining on fresh-cell data   (config_spme_nn.yaml)
2. dataset generator v5     -> fresh + degraded  5. PINN fine-tuning on degraded data   (config_spme_pinn.yaml)
3. copy CSVs into data/ (manual rename)          6. figures + error tables              (plot_result_figures.py)
```

The single entry point is:

```bash
python main.py <config.yaml>
```

`main.py` dispatches from the config keys `model_type` and `method`.

## Quick Start: SPMe

### 1. Install dependencies

```bash
pip install -r requirements.txt
```

For GPU acceleration, install the PyTorch build that matches your CUDA setup.

### 2. Validate supervised NN mode first

This mode trains the SPMe neural network directly against normalized state labels from the generated CSV files. It is useful for checking whether the network size and input history length can generalize before moving to PINN losses.

```bash
python main.py config_spme_nn.yaml
```

Outputs are written to `save_dir`, by default:

- `results/spme_nn/spme_nn_n.pth`
- `results/spme_nn/spme_nn_e.pth`
- `results/spme_nn/spme_nn_p.pth`
- `results/spme_nn/spme_nn_history.csv`

### 3. Train SPMe PINN mode

After NN capacity looks reasonable, run the SPMe PINN path:

```bash
python main.py config_spme_pinn.yaml
```

The current PINN config starts from the supervised NN checkpoint:

```yaml
pretrained_nn_checkpoint: results/spme_nn/checkpoint_epoch_0002000.pth
```

It trains through sparse SPMe rollout targets using voltage loss, solid/electrolyte lithium inventory losses, SEI degradation estimation, and integration consistency between rolled states and neighboring NN predictions.

## Reproducing The Reference Result

The reference result comes from one run, `results/spme_pinn_direct_exact/`, made with the committed `config_spme_pinn.yaml` (identical to the config stored inside its checkpoints). The reference figures and error tables were taken at **different epochs**, and neither is the final checkpoint:

| Item | Source |
|---|---|
| Training/validation data figures (`fig01`, `fig02_*`) | `data/*_soh90.csv` |
| Loss, parameter-trajectory and NN-state figures (`fig03`-`fig08`) | `results/spme_pinn_direct_exact/checkpoint_epoch_0022500.pth` |
| Parameter-error and validation-error tables | `results/spme_pinn_direct_exact/checkpoint_epoch_0023500.pth` |
| Fresh-cell NN initialization | `results/spme_nn/checkpoint_epoch_0002000.pth` |

Expected values at epoch 23,500: `delta_sei` = 5.0682e-7 m (true 5.05188e-7 m, +0.32%), `epsilon_e_n` = 0.055401, `nLi_s` = 0.248474 mol. Bare-NN validation voltage RMSE at epoch 23,500 is 6.46 / 5.96 / 5.65 mV for BJDST / FUDS / US06. The run continued to epoch 100,000 (`checkpoint_latest.pth`, `delta_sei` = 5.090e-7 m). It ran on a laptop CPU at about 3-3.6 s per epoch (epoch 23,500 after about 22 hours), without W&B.

`results/` is git-ignored. The checkpoints above are distributed separately; place them at the paths shown.

Steps:

```bash

python plot_result_figures.py --config config_spme_pinn.yaml \
  --checkpoint results/spme_pinn_direct_exact/checkpoint_epoch_0023500.pth \
  --output-dir results/spme_pinn_direct_exact/result_figures_ep23500
```

`plot_result_figures.py` writes `fig01`-`fig08` (add `--formats pdf` for PDF), `parameter_estimation_error.csv`, `trajectory_state_estimation_errors.csv` and `numerical_error_summary.txt`. ### Network Options

| Option | Example | Meaning |
|---|---|---|
| `batch_size` | `256` | Training batch size. |
| `layer_lstm` | `1` | Number of LSTM layers in each state block. |
| `hidden_lstm` | `32` | LSTM hidden dimension. |
| `layer_fc` | `1` | Number of fully connected hidden layers after the LSTM. |
| `hidden_fc` | `128` | Width of each fully connected hidden layer. |
| `activation` | `tanh` | Activation used by the custom LSTM/FC block. |
| `network_output` | `raw` | SPMe uses SPM-style `CustomLSTM` output scaling to raw physical concentrations. |
| `epochs` | `1000` | Number of training epochs. |
| `lrate` | `0.001` | Initial learning rate. |
| `decay_step` | `500` | Epoch after which multiplicative LR decay starts. |
| `decay_rate` | `0.999` | Per-epoch LR multiplier after `decay_step`. |
| `seed` | `1234` | NumPy and PyTorch random seed. |

SPMe uses the same architecture principle as the original SPM implementation:

- `nn_models[0]`: anode solid concentration network
- `nn_models[1]`: electrolyte concentration network
- `nn_models[2]`: cathode solid concentration network

Each model receives the same normalized current/voltage history and predicts one raw concentration block. The packed state order is:

```text
[c_s_n, c_e, c_s_p]
```

The output ranges are subsystem-specific:

- anode: `p.c_n_soc0` to `p.c_n_soc100`
- electrolyte: `p.ce_min` to `p.ce_max`
- cathode: `p.c_p_soc100` to `p.c_p_soc0`

NN mode trains with grouped normalized losses for scale balance:

```text
loss = loss_c_s_n + loss_c_e + loss_c_s_p
```

### Sequence And Integrator Options

| Option | Example | Meaning |
|---|---|---|
| `k` | `90` | LSTM input history length only: number of historical current/voltage samples fed to the network. |
| `h` | `1` | Model integration step in seconds for SPMe rollout. |
| `pinn_rollout_steps` | `120` | Dense PINN rollout length for `standard` mode. In sparse modes this is metadata; `pinn_rollout_eval_steps` controls target offsets. |
| `pinn_rollout_mode` | `standard`, `direct_exact`, `fast_rk4` | Rollout strategy for PINN targets. See sparse rollout notes below. |
| `pinn_rollout_eval_steps` | `[1, 2, 5, 10, 30, 60, 120, 240]` | Sparse target offsets from the end of the input window for `direct_exact` and `fast_rk4`. |
| `pinn_allow_partial_rollout_windows` | `true` | Keep late-profile windows even when only some sparse future targets are available; invalid targets are masked from loss. |
| `fast_rk4_chunk_h` | `3` | For `fast_rk4`, roll to one second before each sparse target using RK4 chunks up to this duration with averaged current. |
| `integ_type` | `0` | Solid-state integrator option: `0` = RK4, `1` = Euler. |
| `electrolyte_integrator` | `implicit` | SPMe electrolyte integrator: `implicit` for training, `rk4` for debugging/reference. |
| `electrolyte_substeps` | `1` | RK4 electrolyte substeps when `electrolyte_integrator: rk4`. Keep `1` for implicit training. |

For PINN-SPMe training with one-second data, use:

```yaml
h: 1
electrolyte_integrator: implicit
electrolyte_substeps: 1
```

The explicit RK4 electrolyte path is retained as a reference/debug option.

PINN rollout modes:

- `standard`: dense rollout using `model.forward(...)` and `i_future_ave`; every rollout column corresponds to a regular integration step.
- `direct_exact`: sparse rollout at `pinn_rollout_eval_steps`; each target uses one averaged-current exact solid step to `step - 1`, then a final `h=1` step with sampled target current. Electrolyte still uses the configured SPMe electrolyte step.
- `fast_rk4`: sparse rollout at the same target steps; each target advances to `step - 1` through RK4 chunks of up to `fast_rk4_chunk_h`, then takes a final `h=1` RK4 step.

For sparse modes, `pinn_rollout_steps` is metadata only; the active targets are `pinn_rollout_eval_steps`.

### SPMe PINN Loss Options

Used by `config_spme_pinn.yaml` with `method: pinn`.

| Option | Example | Meaning |
|---|---|---|
| `w_v` | `1.0` | Voltage loss weight. |
| `w_li_s` | `1.0` | Solid lithium conservation loss weight. |
| `w_li_e` | `1.0` | Electrolyte lithium conservation loss weight. Keeping this enabled helps prevent unphysical electrolyte drift. |
| `w_integ` | `1.0` | SPM-style integration consistency loss weight across anode, electrolyte, and cathode blocks. |
| `estimate_delta_sei` | `true` | Train one scaled SEI thickness parameter, `delta_sei_scaled`. |
| `delta_sei_init` | `1.0e-12` | Initial SEI thickness estimate in meters. Fresh-cell SEI is zero. |
| `delta_sei_lower` / `delta_sei_upper` | `0.0` / `2.0e-6` | Physical clamp range for estimated SEI thickness. |
| `delta_sei_true` | `5.05188e-07` | Optional diagnostic target for W&B/history logging. |
| `epsilon_e_n_true` | `0.0560283` | Optional diagnostic target for W&B/history logging. |
| `nLi_s_fresh` | `0.2840` | Fresh solid lithium inventory. Degraded `nLi_s_est` is derived from SEI lithium loss. |
| `R_f_n_base` | `0.0` | Fresh-cell anode film resistance base. `R_f_n_est = R_f_n_base + delta_sei_est / kappa_sei`. |
| `rho_sei`, `M_sei`, `kappa_sei` | `1690.0`, `0.162`, `1.0e-6` | SEI material constants used to map thickness to lost lithium and film resistance. |
| `supervise_states` | `false` | Kept as a config marker; SPMe PINN follows SPM style and does not use true-state supervision loss. |

SPMe PINN loss is:

```text
loss = w_v * loss_voltage
     + w_li_s * loss_solid_lithium
     + w_li_e * loss_electrolyte_lithium
     + w_integ * loss_integ
```

Boundary conditions are handled as hard constraints through solid state reconstruction, SPMe integration, conservative electrolyte FVM, and MATLAB-aligned `C_ce` electrolyte reconstruction. There are no extra soft BC loss terms.

SPMe PINN estimates degradation through one scalar SEI thickness. The derived quantities are:

```text
nLi_sei_est = (2 * rho_sei / M_sei) * a_s_n * Area_n * L_n * delta_sei_est
nLi_s_est = nLi_s_fresh - nLi_sei_est
epsilon_e_n_est = epsilon_e_n_fresh - a_s_n * delta_sei_est
R_f_n_est = R_f_n_base + delta_sei_est / kappa_sei
```

Lithium inventory losses use bare NN predictions only and compare them to these derived targets. They do not use rolled SPMe states:

```text
loss_li_s = RMSE((nLi_s_nn - nLi_s_est) / nLi_s_init)
loss_li_e = RMSE((nLi_e_nn - nLi_e_est) / nLi_e_init)
```

The current PINN config keeps `w_li_e: 1.0`. This is important because voltage loss alone can reduce while the raw NN electrolyte state moves into unphysical concentration ranges.

For PINN integration consistency, SPMe follows the original SPM batching strategy: batches contain consecutive windows from a single profile, each NN is evaluated once for that batch, SPMe rolls the predicted initial states forward, and `loss_integ` compares rolled future states with already-computed neighboring NN predictions by tensor slicing. Shifted windows are not sent through the LSTMs again.

For `standard` rollout, integration consistency uses dense rollout columns. With `train_window_stride: 5`, rolled `t+5`, `t+10`, `t+15`, ... states are compared to NN windows `+1`, `+2`, `+3`, ...

For sparse modes (`direct_exact` and `fast_rk4`), integration consistency uses only sparse eval steps divisible by `train_window_stride`. With the current:

```yaml
train_window_stride: 5
pinn_rollout_eval_steps: [1, 2, 5, 10, 30, 60, 120, 240]
```

the integration loss uses `5, 10, 30, 60, 120, 240`, and treats `1` and `2` as voltage/inventory-only sparse targets. The mapping is:

```text
eval step 5   -> NN window +1
eval step 10  -> NN window +2
eval step 30  -> NN window +6
eval step 60  -> NN window +12
eval step 120 -> NN window +24
eval step 240 -> NN window +48
```

In `method: nn`, the network is trained directly against state labels using grouped normalized losses for scale balance. The outputs and plots remain raw physical concentrations.

Dataset provenance:

- All files are produced by `generate_pinn_spme_training_data_LGM50_v5.m` in LGM50 and copied here with a manual rename: fresh-cell `X.csv` -> `spme_X.csv`; degraded-cell `X.csv` -> `spme_X_soh90.csv`; `id_HPPC_*.csv` -> `id_HPPC_*_soh90.csv`.
- The degraded cell is repeat 15 of the LGM50 Safari-SEI cycling run `20260702_034413` (about 1,500 cycles, `delta_sei` = 5.05188e-7 m, `epsilon_e_n` = 0.0560, solid Li 0.2840 -> 0.2486 mol). "soh90" is a label only, not a computed SoH.
- Drive cycles start at SoC 0.9 and stop at 2.5 V; HPPC files are 120 s rest + 10 s pulses at SoC 0.9/0.75/0.6/0.45/0.3. In the `_soh90` files the `soc` column is on the fresh-cell scale (DST starts at 0.73 because Li lost to SEI is removed from the anode).

Train/validation naming is swapped between the two configs on purpose. The file names reflect the generator's roles. `config_spme_nn.yaml` trains on fresh `spme_train_{BJDST,FUDS,US06}.csv` and validates on `spme_val_DST.csv`. `config_spme_pinn.yaml` trains on `spme_val_DST_soh90.csv` plus the five HPPC files (file weights 1.0 / 0.2 each) and validates on `spme_train_{BJDST,FUDS,US06}_soh90.csv`.

Row timing:

- `_soh90` files (generated 2026-07-07): row 1 is the initial state with `current_A = 0`; row k holds the state and voltage after applying row k's current.
- Fresh files (generated 2026-06-30, used for NN pretraining) predate that fix: the voltage in row k was computed with the current of row k-1. They can be converted exactly with `python tools/realign_current_column.py <in.csv> <out.csv>` (shifting `current_A` down one row reproduces the regenerated degraded files to machine precision). Retraining the NN on realigned fresh data is an open item.

The degraded files were regenerated three times under the same names. Older versions exist only in git history (`git show <commit>:data/<file>`):

## Tests And Verification

Run the SPMe unit and consistency tests:

```bash
python -m unittest tests.test_spme -v                         # pack/unpack, conservation, electrolyte integrators
python tests/test_spme_consistency.py --strict                # Python SPMe vs MATLAB SPMe reference behavior
python -m unittest tests.test_spme_degraded_dataset_rollout -v # true degraded parameters reproduce the _soh90 voltage

python tests/test_spme_integrator_stability_sweep.py          # electrolyte time-stepping stability study
```

Run the MATLAB cross-check when MATLAB is available:

```bash
export PATH="/Applications/MATLAB_R2025b.app/bin:$PATH"
python -m unittest tests.test_spme_matlab_cross_run -v
```

The MATLAB cross-run test intentionally requires MATLAB. It should not be skipped silently because the comparison is only meaningful when both Python SPMe and MATLAB SPMe execute.

## Known Issues

- **NaN from negative electrolyte concentration.** The NN outputs raw `c_e` with no positivity constraint, and `electrolyte_conductivity` evaluates `c^1.5`. With `w_integ = 0` or `w_li_e = 0`, `c_e` can drift negative and the loss becomes NaN. Keep both weights above zero.
- **Sparse integration loss depends on the stride.** Only `pinn_rollout_eval_steps` divisible by `train_window_stride` feed `loss_integ`. Keep them consistent if you change the stride.
- **Disk use.** The reference run used `checkpoint_every: 100` (about 1,000 checkpoints, 34 GB). The config now uses 500, which still saves epochs 22,500 and 23,500.
- **Row timing.** Fresh and degraded datasets use different row conventions (see Data). `tools/realign_current_column.py` converts old-timing files exactly by shifting `current_A` down one row; the fresh NN-pretraining files have not been realigned yet.
- **Unimplemented flags.** `estimate_nLi_s` and `estimate_nLi_e` are not implemented; `delta_sei` is the only trainable physical parameter, and setting either flag to true stops training with an error.
